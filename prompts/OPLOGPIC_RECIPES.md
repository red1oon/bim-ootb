# OplogPic recipes

## Why (owner, 2026-10-14)
"It's a nice idea where it stores a user's common ops to apply to any target similar image or text. I would like that." A recipe is the log's own steps, saved: a small parameter list that the page replays on a new target. It needs no new engine: it re-issues ordinary log entries.

## Prior art checked 2026-10-14 (official pages only; nothing else is claimed)
- Adobe, [Record an action](https://helpx.adobe.com/lt/photoshop/desktop/automate-tasks/create-record-actions/record-an-action.html) and [Add commands to an action](https://helpx.adobe.com/be_en/photoshop/desktop/automate-tasks/create-record-actions/add-commands-to-an-action.html): Photoshop records a sequence of steps in the Actions panel for later playback; tool operations such as brush strokes can be recorded when tool recording is on.
- Photopea, [Actions](https://www.photopea.com/learn/actions): a Record button captures steps into an action; Apply runs an action on the current document; actions sit in Action Sets. Its 2019 [release notes](https://blog.photopea.com/photopea-4-1-actions-new-filters.html) say ATN files can be loaded and stored but not all actions can be recorded or applied (an old page).
- Adobe, [Copy and paste edit settings](https://helpx.adobe.com/lightroom-classic/help/copy-paste-settings.html) (Lightroom Classic): copy a photo's settings, choose which adjustments carry over, paste onto one or many photos.
- Demand evidence is INDIRECT: Adobe's own guide on [making and selling Lightroom presets](https://www.adobe.com/in/creativecloud/roc/blog/photography/how-to-make-and-sell-lightroom-presets.html) and vendor blogs describe a preset market; no independently verified sales figures were found. This spec therefore claims convenience, not novelty and not a measured market.
- What OplogPic can say about ITSELF, because tests will prove it (never as a comparison): a recipe is a plain list of parameters; applying it appends ordinary log entries, so the document stays self-contained; recipes verify by the same replay and hash machinery; a small recipe fits a QR code or a link; nothing goes to a server.

## R.1 What a recipe is
`{format:'oplogrecipe', v:1, name, saved, steps:[...]}`, steps = ordinary editor ops with two kinds of placeholder:
- `"layer":"$target"` = the layer chosen when the recipe is applied.
- adjustment / filter ids are LOCAL (`"id":"$a1"`, `"$a2"`...; `adjset` refers to them); on apply each gets a fresh real id (`LayerOps.nextId`).
Eligible ops in v1 ("target-relative": they act on whatever is there, not on fixed positions): `adjust` (every kind: hsl, levels, curves, threshold, posterize, invert, gradmap, gblur, sharpen), `adjset`, `fx` (shadow, stroke), `set` (opacity / blend mode of the target), `name` of the target. NOT eligible in v1: `stroke`, `smudge`, `shape`, `grad`, `sel`, `mask`, `img`, `imgset`, `xform`, `fill`, `dab`, structural ops (`layer`, `del`, `mv`, `group`...), `amend`. They are tied to one picture's positions, pixels or layer structure (a later version can add canvas-relative ones; see LATER).
Limits: 1..32 steps, name 1..40 characters, total JSON <= 8 KB.

## R.2 Making a recipe (History panel)
"Make recipe": tap the entries to include (checkboxes appear), name it, Save. The page converts the chosen entries: the layer of an `fx` / `set` / `name` entry becomes `$target`; adjustments created inside the selection get local ids; an `adjset` is kept only if its adjustment is also selected. Anything not eligible is refused with a specific message ("Strokes and shapes are tied to one picture; v1 recipes hold effects, adjustments and filters") and nothing is saved. Recipes live on the device (IndexedDB `oplogpic`, store `recipes`); list, rename, delete in a "Recipes" panel under Advanced.

## R.3 Applying a recipe
Choose the target layer (the active layer), pick the recipe, Apply: the page validates the recipe and the target (a normal, visible-or-hidden layer, not a group or adjustment, for recipes that contain `$target` ops), expands placeholders, and logs the concrete ops one by one through the normal paths (so every op is validated by its own module and the log never depends on the recipe afterwards). One Apply = k ordinary entries (k = number of steps); "Undo recipe" undoes exactly those k. A recipe without `$target` steps (only adjustments) applies to the whole document and needs no target.

## R.4 Sharing
- **Recipe file** `.oplogrecipe`: gzip of the JSON plus `check:{n, head}` (hash of the steps), same container code as the carry file (`editor/carry_file.js`: damaged / cut / newer-version messages reused). Open it with the Recipes panel's Import, or drop it on the page.
- **Link and QR:** `#r1=<compressed steps>&h=<fingerprint>` (parameters only, so a typical recipe is a few hundred bytes and fits the existing QR view, 2,953-byte capacity). Opening the link or scanning the QR shows "Import recipe 'Soft glow' (3 steps)?" with the steps listed; nothing is applied or saved until the user taps Import, and an imported recipe is only ever applied by an explicit Apply.
- **Safety:** every recipe, from any source, is validated against the eligible-op list and each op's own validator before it is saved or applied; blob ops (`img`, `imgset`), unknown ops, unknown keys, prototype-pollution keys (`__proto__`, `constructor`, `prototype`), more than 32 steps and > 8 KB are refused with a message.

## R.5 Hypotheses (thresholds fixed NOW; HYPOTHESES.md "Level 3a" copies this table before any code)

Honest limits fixed now: v1 recipes hold only target-relative steps (effects, adjustments, filters, opacity / blend of the target); no strokes, shapes, gradients or text yet; no "record while I work" mode (a recipe is made from History entries you pick); no batch over many files; no import of other editors' action or preset files; recipes are not live (applying copies the steps: editing the recipe later does not change documents that used it); an Apply is k log entries, not one; the demand case rests on indirect evidence (see Prior art).

## LATER (written so nobody re-litigates)
1. **Canvas-relative steps**: gradients, shapes and selections stored as fractions of the canvas so they fit any size. 2. **Caption style recipes** (`txt` settings applied with Edit text). 3. **Record mode** (log what you do for the next N steps). 4. **Batch** (apply to every layer of a type, or to a folder of `.oplogpic` files). 5. **A recipe gallery you host yourself** (a static folder of `.oplogrecipe` files; no server logic).
