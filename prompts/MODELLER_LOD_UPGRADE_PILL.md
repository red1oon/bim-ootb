**What is ported (same maths, same order, no clock, no random, every loop over sorted keys):**
1. Per plate: a frame from the minimum-area rectangle of its in-plane triangle edges (thickness axis = smallest world extent); the plate box in that frame.
2. Per member: centroid + long axis (largest-eigenvalue direction of the vertex covariance, sign fixed by the largest component), its end positions along that axis.
3. Contact member x plate: bounding boxes first; then triangle-box separating-axis test (Akenine-Moller) plus a ray-parity test for the plate-box corners inside the member mesh; the contact interval along the member axis = the member triangles clipped to the plate box (Sutherland-Hodgman, 6 planes). Interval shorter than 1e-6 m = touch only. End contact (A, B or AB) when the interval reaches within `weld_contact_end_tol_mm` of a member end, otherwise THROUGH (T).
4. Weld = two triangular fillet beads (8 triangles each, 24 vertices) laid on the +face of the plate along the two outer edges of the member section, length = the overlap interval. Size = AISC 360-16 Table J2.4 minimum for the thinner part (plate thickness read from its name, else measured; member leg thickness read from its name). Bead end caps are wound outward from the bead's own centroid (the 2026-11-18 correction).
5. Refused, never dropped: a contact whose member axis is not parallel to the plate plane (|axis . plate normal| > 0.05) gets `REFUSED ... member axis not parallel to the plate plane ...` (the 26 perpendicular "Section run" contacts on the Shed); a member that does not cross the plate-face plane gets `... no seam`. ## P3 SPEC (2026-11-18) — Layer split (pack `layers`, label "Layers")
**Issue it proves or disproves:** *"the browser result differs from the proven Python result"* for the layer split of the extractor (BIMCompiler `DAGCompiler/python/extractIFCtoDB.py`: `compile_layer_geometry` L1403, `_layer_intervals` L1330, `_slice_slab` L1290, `_cross_section_loops` L1148, `_cap_triangles` L1213, `_orient_coherently` L1066, refusals `§LAYER-REFUSE` L1033/L1440, and the DB writer `component_geometry_layers` L325/L1579) as consumed by `~/Projects/Jebel/lod_sandbox/jpam/build_jpam.py` section A (part names, change rows, frame). Oracle output: the JPAM DB (220 `GEN-LY-*` parts, 9 `REFUSED ... Layer split` rows).

**What the source DB really carries (measured on the ARC extract):** the extractor compiled the split in place. For the 88 split hosts the stored host mesh already IS the concatenated layer slabs (same hash key as before), indexed by `component_geometry_layers` (`layer_seq`, `material_name`, `thickness_m`, `face_start`, `face_count`); the 9 refused hosts still hold their one envelope solid. So the pack reads the DB in two honest states, never mixing them:
1. **Sliced state** (the host's hash has index rows): each part = the triangles `face_start .. +face_count` of the host mesh, but only after the pack re-verifies them against the authored tables (never trusts the index blindly): stated thickness equals the slab extent along the layer axis within `layer_tol_mm`; the slab's span along the axis equals the authored interval for that layer (the extractor's `_layer_intervals`, absolute else relative anchoring, direction sense applied); each slab watertight with positive volume.
2. **Envelope state** (no index rows): the port of the slicer itself: weld (1e-9 m), edge-manifold check, coherent outward winding, signed volume, authored intervals, Sutherland-Hodgman clip of the crossing triangles, caps from the cross-section loops (edge-keyed chaining, even-odd nesting for holes), weld, watertight proof, per-slab extent proof, volume re-sum proof. Differences from the oracle, stated: cap triangulation is ear clipping with hole bridges instead of GEOS constrained Delaunay. Both use only the loop points (no Steiner points) so the vertex SET and every area are identical; the triangle fan inside a cap may differ. The witness therefore compares vertex sets and volumes, not triangle order, for this state. Self-intersecting loops are not tested (the oracle's `is_valid`); a cap whose triangulation fails or whose area differs is a REFUSED, never a guess.

**Refusals, never dropped, reason text identical to the extractor's (`§LAYER-REFUSE`):** `LayerSetDirection missing/unknown (None)`, `DirectionSense missing/unknown`, authored total missing, `material_layers has N rows ...`, a layer thickness missing, thicknesses do not re-sum, envelope not watertight / not orientable / nested cavity / zero volume, `body span [a,b] (extent e) does not align with the authored layer set (total t, offset o, sense s) under absolute OR relative anchoring`, slab extent / volume / empty-slab proofs. Order of the checks = the Python order. Each becomes a change row `REFUSED` with the reason; the host stays visible (no part is written, so P1's seeding keeps it).

**Parts:** `GEN-LY-<host>-<seq>`, class `IfcBuildingElementPart`, name `<material> <th*1000:.1f> mm (layer <seq> of <set>)`, host storey, host colour, world mesh = host transform (Euler rx,ry,rz as in the extractor's `R_recon`) applied to the local slab, own bbox centre (spec §5), provenance `generated:layers`, `parts_of:[host]` (so `element_parts` host -> part is derived and P1's seeding hides the host; the oracle writes exactly these rows). Change row ADDED: rule `Layer split along IfcMaterialLayerSetUsage <AXIS>`, detail `host=<cls> "<name>" | layer <seq> <material> | stated <th> mm | measured <m> mm | storey <s>` (the oracle's text). A layer the authored geometry clips away has no part and no row (extractor ruling 2026-07-31) and is logged `§LODUP_LAYER_CLIP`.

**Rules as data:** `lod/rules/layer_defaults.json`: `layer_tol_mm` 0.5 (the extractor's `LAYER_TOL`), `layer_sum_tol_mm` 0.001 (`LAYER_SUM_TOL`), `layer_volume_rtol` 0.0001 (`LAYER_VOL_RTOL`), `layer_min_count` 2 (`layer_count > 1`); every row `default:`. No project value.

**Engine change (generic, additive):** `lod_reader.js` gains `layers` (hosts, material_layers, host mesh from `component_geometries` else `base_geometries`, the layer index, transform) and `rgba` on `meta`; `world()` is untouched. `lod_ui.js` is NOT edited (sha256 asserted); one line in `packs.json`; `modeller.html` is not edited either (the dialog loads packs from `packs.json`).

**Frame:** the Modeller shows the extractor frame (`world = R(rx,ry,rz) v + centre`). The oracle parts live in the combined frame (extractor frame + one fixed translation: `site_normalization` offset minus a measured shift). ## P3 FIX SPEC 2 (2026-11-18, review of #3243) — Truss welds judge steel-to-steel pairs only
Issue it proves or disproves: *"the weld pack welds anything shaped like a member against anything shaped like a plate"*. On the ARC extract the IfcPlate rows are cladding / panels and the IfcMember rows include curtain-wall members; welding them is invented engineering. An element's stated materials = `elements_meta.material_name` plus the material of each layer of its layer set (`material_layers`), read by `lod_reader.js` as `meta.mat` and `meta.layerMats`. BOTH the member and the plate must match; an element that does not is not judged (no contact test, no weld, no change row: it is outside the rule, not refused), and the run logs `§LODUP_WELD_GATE members_steel= plates_steel= members_gated_out= plates_gated_out=`. The value may be a list or a comma-separated string (the dialog's edit box returns a string); an empty value turns the gate off. `appliesTo` (= the run's judged contacts) therefore counts steel-steel contacts only; 0 is shown as "not applicable here". Option `noMaterialGate` (the red control) turns the gate off.
