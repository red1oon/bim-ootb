# ⚠ DO NOT REMOVE — Milestone 1: W-MFG-WIRE (scope: wire the Manufacturing Order window; read the log after every run)

Parent doc: `Manufacturing Model Milestones and Contracts.md` (§Witnessed milestones, row W-MFG-WIRE).

## Issue it proves or disproves
The seed defines the Manufacturing Order window (AD_Window 53009, 13 tabs) but a user cannot open it:
(a) 8 of its tables have no physical table and 2 more are column-short, (b) no active menu path reaches it.

## Facts measured 2026-10-14 (seed + reference Postgres)
- 8 PP tables with AD_Table/AD_Column rows but no physical table: PP_Order_Workflow, PP_Order_Node_Product,
  PP_Order_Node_Asset, PP_Order_NodeNext, PP_Cost_Collector, PP_Cost_CollectorMA, PP_WF_Node_Product, PP_WF_Node_Asset.
- Column-short physical tables vs reference Postgres: PP_Order_Node (30 of 70), PP_Order_Cost (20 of 24).
- Menu: legacy path 53014 Manufacturing Management > 53052 Production Management > 53053 Discreet Manufacturing >
  53055 Manufacturing Order. All four are IsActive='N' upstream (EntityType EE01, disabled by default) so the seed
  carries their AD_TreeNodeMM nodes but no AD_Menu rows. `ad_parser.getMenuTree` filters IsActive='Y' and turns a
  node whose parent is missing into a root, so all four rows are needed or the leaf floats to the top level.

## Design (no new mechanism)
- Ship as its OWN patch `erp/patches/mfg.sql`, generated by `erp/patches/build_mfg_patch.py` (user request 2026-10-14: separate from
  ad_seed.db.sql). `idempiere.html` loader applies `ad_seed.db.sql` then `mfg.sql` on every load (DB-changes = patch + self-heal loader). DDL and rows are EXTRACTED from reference Postgres, never typed.
- Column widening = `ALTER TABLE ... ADD COLUMN` for each reference column absent from the seed (loader tolerates
  the duplicate-column failure on re-run, same as the existing fact_acct precedent).
- Menu: the four AD_Menu rows copied verbatim with IsActive forced 'Y'. This is an ordinary admin activation of an
  upstream-disabled EE01 menu, flagged in the patch comment (same precedent: seed_hba_payroll_windows.js).

## Witness `erp/tests/witness_mfg_wire.js` (log tag `§MFG`)
Loads ad_seed.db + the patch exactly as the loader does, then asserts:
- M1 8 tables exist physically.  M2 for every table behind the 13 tabs, every AD_Column (non-virtual) has a physical
  column; failures NAME the table.column.  M3 menu: walking `AD_TreeNodeMM` up from AD_Menu 53055 reaches a root
  through active AD_Menu rows only, and `getWindowFromMenu` returns 53009.  M4 `getWindow(53009)` returns 13 tabs.
- Verdict prints INCONCLUSIVE (not PASS) if the window has 0 tabs or the tab-table population is empty.
- Deliberate breaks (env `MFG_BREAK=col|menu|table`) must turn it red and name the culprit.
