## Groups and clipping masks (logged BEFORE implementation; verdicts filled in by `doc/run_groups.js` results)
Semantics chosen (Photoshop-like): group = ordered children + own mode/opacity/mask. `pass-through` group: children blend directly with the backdrop, then the result is
lerped with the backdrop by opacity*mask. Any other group mode = isolated: children composite on a transparent buffer, then the group is blended like a layer. Clipping:
a clipped layer is composited source-atop onto its base layer (base's alpha is the shape); the base+clips unit is then blended with the BASE layer's mode/opacity/mask
("blend clipped layers as group" ON). Clip bases must be layers (not groups) in schema v2.

## Adjustment layers: invert, levels, threshold, posterize (logged BEFORE implementation)
Schema v2 op `{op:'adjust', id, kind, params, opacity, mask, parent?}`; it transforms the composite beneath it within its parent context (pass-through: whole backdrop; isolated group: that group's content), then
result = lerp(before, adjusted, opacity*mask) on the straight colour; alpha is never changed. Only in `gamma: "encoded"` documents (behaviour in linear light is unknown, so rejected). Definitions (from the PS integer model, NOT fitted):
levels: x = clamp((c - ib/255) / ((iw - ib)/255)); x = x^(1/gamma); out = clamp(ob/255 + x*(ow - ob)/255), params in PS integer units, gamma_x100 in 1..999 (ag-psd/PSD store midtone as int16/100);
threshold: white iff round(255*(0.3R+0.59G+0.11B)) >= level (level 1..255); posterize: out = floor(c*(255/256)*n)/(n-1), n in 2..255, which reproduces the PS 8-bit mapping floor(v*n/256)/(n-1) exactly (n=2 cuts at 128); invert: 1 - c.
Canonical code may not use Math.pow (not bit-exact across engines), so x^y is a deterministic routine using only + - * / on doubles (exponent/mantissa split, atanh-series log2, Taylor exp2).

## Curves adjustment (logged BEFORE implementation)

## Gaussian blur filter op vs scipy (logged BEFORE any code or measurement; `filters/blur.js`, `filters/run_blur.js`, `npm run blur`; terminal session)
Context: README listed blur as the open "filter question": a blur reads neighbours, unlike every op so far. Design (stack.js and the doc schema are NOT edited): a filter is one tiny op-log entry `{op:'blur', layer, sigma, rect?:[x,y,w,h]}` applied by `filters/blur.js` (`applyOp` wraps `S.apply`). Semantics fixed now: acts on the layer's premultiplied float32 RGBA (4 independent channels); separable Gaussian, radius r = floor(4*sigma + 0.5) (scipy truncate=4.0), kernel w_i = exp(-0.5 i^2 / sigma^2) normalised, computed in double with `S.powDet` (no Math.exp, which is not bit-exact across engines) then rounded to float32; accumulation left to right with Math.fround at every step; edge mode 'reflect' (d c b a | a b c d | d c b a, repeated for r larger than the layer). With `rect`, output pixels INSIDE the rect are the blur of the source (neighbours outside the rect are read), pixels outside are untouched. sigma <= 0 is the identity.
Reference: `scipy.ndimage.gaussian_filter(a64, sigma, mode='reflect', truncate=4.0)` per channel on the float64 copy of the same premultiplied layer (scipy version recorded in the output).

## Hard brush, stroke op and smudge op (logged BEFORE any code or measurement; `filters/brush.js`, `filters/run_brush.js`, `filters/check_brush_ref.py`, `npm run brush`; terminal session)
Context: the only brush so far is the soft round `dab`, so every sample looks soft, and "real brush data" (op-log size of a real stroke) is unmeasured. New ops live in `filters/brush.js` (`applyOp` wraps `S.apply`, like blur); `stack.js` and the doc schema are NOT edited. All maths uses only + - * / Math.sqrt, every step through Math.fround (canonical rule). Layers are premultiplied float32 RGBA, as for `dab`.
Definitions fixed now:
- `hdab {layer,x,y,r,c:[r,g,b],a}`: for the pixel centre (px+0.5, py+0.5), d = sqrt(dx^2+dy^2) in float32; coverage = clamp(r - d + 0.5, 0, 1) * a (1-pixel linear anti-aliased edge: exactly 0.5*a on the circle); then the same premultiplied source-over as `dab`. Scan box floor(x-r-1)..ceil(x+r+1), clipped to the layer.
- `stroke {layer, kind:'hard'|'soft', pts:[[x,y],...], r, c, a, spacing?}`: expanded deterministically to dabs of the given kind (`hdab` or the existing soft `dab`) at distance `step = max(spacing*r, 1)` along the polyline (spacing default 0.25); first dab at pts[0], the remainder of the step is carried across vertices; one point = one dab. A stroke of N dabs is ONE log entry.
- `smudge {layer, pts, r, s}` (s in [0,1]): dab positions as for a stroke with spacing 0.1 and kind soft; each position snaps to the integer pixel anchor (floor x, floor y) (no resampling; known limit). Carried footprint P (premultiplied RGBA over the integer offsets |i|,|j| <= ceil(r)) starts as the layer content under the first anchor. For every next anchor and every offset with falloff f = (1 - d^2/r^2)^2 > 0 (d < r) and an on-canvas pixel: B = layer pixel before; w = s*f; layer = B*(1-w) + P*w; then P = s*P + (1-s)*B (all 4 channels). s = 0 is the identity. Every result is a convex combination of existing values.
Honest limits fixed now: no pressure/tilt/jitter; the smudge spec is mine, there is no Photoshop reference for what a smudge "should" look like (the look is DEFERRED to a person); the numpy reference re-implements the same definitions, so it finds coding bugs, not wrong definitions (the cairo check for the hard edge is the one independent external reference).

## Blur brush (logged BEFORE any code or measurement; `filters/brush.js` kind 'blur', `filters/run_blurbrush.js`, `npm run blurbrush`; terminal session)
Context: owner's phone test of the published editor: "Working except the blur". The Blur tool applies one `blur` rect op (sigma 4, fixed 128x128 px square) per tap: small effect and a visible square edge, and it cannot be dragged like the other tools. Fix: Blur becomes a brush stroke.
Definition fixed now: `{op:'stroke', kind:'blur', layer, pts, r, s}` (s in (0,1], strength; `c` and `a` ignored). Dab positions as for the smudge (PositionBuilder spacing 0.15, soft). For each position the integer anchor (floor x, floor y) and R = ceil(r): the square [ax-R, ay-R, 2R+1, 2R+1] clipped to the layer is blurred with the existing Gaussian (sigma = max(1, 0.2*r), reads neighbours outside the square, canvas edges reflect, writing into a SEPARATE buffer); then every pixel of that square with falloff f = (1 - d^2/r^2)^2 > 0 becomes B*(1-w) + Blurred*w with w = s*f (all 4 premultiplied channels). So blur fades out smoothly toward the dab edge (no square edge), later dabs see earlier ones, and every result is a convex combination of existing values. Only + - * / sqrt, Math.fround at every step; the Gaussian kernel is the deterministic one from `filters/blur.js`. The editor's Blur tool uses the size slider for r and the Smudge-strength slider for s (labelled Smudge / blur strength); the old rect `blur` op stays in the engine for existing logs.

## Level 1a: layer delete / hide / reorder / rename (logged BEFORE any code; `editor/run_layers.js`, `npm run editor_layers`; terminal session 2026-10-11)
Context: RESUME_PSD_OPLOG_POC.md "NEXT: Level 1". Layer management is missing from editor v0.2. Four new editor-log ops, handled in `editor/layer_ops.js` (called from `editor/editor.js` applyOp); `stack.js`, the doc schema and the existing ops are NOT edited. Log stays `format psd-oplog-editor v 1`; old logs load unchanged; a log that uses the new ops is not readable by an older page (it rejects unknown ops).
Definitions fixed now:
- `{op:'del', layer}` removes a layer (state, `order`, `root`). Layer 0 (Background) cannot be deleted (applyOp throws).
- `{op:'mv', layer, to}` moves the layer to index `to` in `order`/`root` (0 = bottom; applyOp throws if `to` is outside 1..n-1). Layer 0 may not move and nothing may move below it.
- `{op:'vis', layer, v}` v=false hides, v=true shows. Implemented as `l.hid=true; l.keep=<opacity>; l.opacity=0` and the reverse, so the unchanged compositor skips the layer. `set opacity` on a hidden layer updates `keep` only.
- `{op:'name', layer, name}` name = string, 1..40 chars after trim; display only, no pixel effect. Default display name stays "Layer N" / "Background".
- Painting on a hidden layer is refused by the editor (nothing logged).
- Undo/redo: each op is one undo step; undo of `del` restores the layer's pixels bit for bit; ids are `max(order)+1` so an id may be reused after a delete (replay-safe because `del` precedes the new `layer`).
- PSD export (page and Node, byte-identical): layers in `order`; each layer's name written; a hidden layer is written with its REAL opacity and `hidden: true` and is left out of the merged image. Done through an optional `opts.meta` of `exportPsd` (`{id:{name,hidden}}`); without it behaviour is unchanged.

## Level 1c: selection (rect / ellipse / invert / none) (logged BEFORE any code; `editor/run_select.js`, `npm run editor_select`; owner agreed 2026-10-11 to do the format-changing items first)
Design: selection is document STATE set by a log op, not pixels. Engine files (`stack.js`, `filters/*`) are NOT edited: when a selection is active, a painting op (`stroke` of any kind, `smudge`) runs on a SHADOW copy of the layer and the result is written back by per-pixel SELECT: inside the selection the shadow's pixel, outside the original pixel. Masks are binary, so no arithmetic blending: inside == the unselected result bit for bit, outside == untouched bit for bit.
Ops (in `editor/layer_ops.js`'s sibling `editor/select_ops.js`, applied before the brush ops in editor applyOp):
- `{op:'sel', kind:'rect', x0,y0,x1,y1}` integers, 0 <= x0 < x1 <= W, same for y. Pixel (x,y) is inside iff x0<=x<x1 and y0<=y<y1.
- `{op:'sel', kind:'ellipse', x0,y0,x1,y1}` same box. cx=(x0+x1)/2, cy=(y0+y1)/2, rx=(x1-x0)/2, ry=(y1-y0)/2; inside iff ((x+0.5-cx)/rx)^2 + ((y+0.5-cy)/ry)^2 <= 1, float64, only + - * /.
- `{op:'sel', kind:'invert'}` flips inside/outside (throws when there is no selection). `{op:'sel', kind:'none'}` clears.
- A new rect/ellipse REPLACES the selection. The selection survives layer changes and applies to whichever layer is painted. `img`/`layer`/`set`/`del`/`mv` ignore it.
- Selection is not exported to PSD. Undo/redo: each `sel` op is one undo step.

## Level 1d: photo import (images stored inside the log as content-addressed blobs) (logged BEFORE any code; `editor/run_photo.js`, `npm run editor_photo`; owner agreed 2026-10-11)
Design: the log stays the truth, so a photo must be IN it. The page scales the picture ONCE to the canvas (browser resampling is NOT deterministic across browsers, so the resampled pixels, not the file, are what the log records) and stores the result as a blob; the op refers to the blob by sha256.
- Op `{op:'img', id, sha}` creates layer `id` (normal, opacity 1, no mask; id must not exist) whose pixels are the blob: W*W*4 bytes straight RGBA8; premultiplied float: a = F(A/255), c = F(F(C/255)*a). A missing blob, wrong size or existing id throws. Handled in `editor/img_ops.js`; `stack.js` and the doc schema are not edited. One op = one undo step (undo removes the layer, redo restores it).
- Blob store: `ed.blobs` Map sha -> Uint8Array. `save()` writes `{format, v:1, W, ops, blobs:{sha: base64}}` with only the blobs the ops use (key `blobs` omitted when none). `load()` verifies sha256(bytes) == key for every blob and throws on mismatch or on a missing blob. Same photo imported twice = ONE blob, two ops.
- Import geometry (contain): scale = min(W/iw, W/ih); dw = round(iw*scale), dh = round(ih*scale); placed at x=floor((W-dw)/2), y=floor((H-dh)/2); the rest is transparent (alpha 0, rgb 0). Image drawn with the browser at high smoothing quality into a W*W canvas, read back with getImageData.
- Persistence: autosave of a log WITH blobs goes to IndexedDB (localStorage's ~5 MB quota cannot hold a photo); logs without blobs keep using localStorage exactly as before. On startup localStorage is read first, then IndexedDB.
- Node exporter (`export_psd.js`) decodes `blobs` into the fold state so saved logs with photos export to PSD.

## Level 1b: history panel, re-edit a past stroke, replay, share-as-link, verify (logged BEFORE any code; `editor/run_history.js`, `npm run editor_history`; terminal session 2026-10-11)
Design (the log is append-only, so nothing in it is ever rewritten):
- **Re-edit** = a new log entry `{op:'amend', i, set:{...}}`. `i` = index of an EARLIER entry that is a `stroke` or `smudge`. `set` keys allowed: `c` (3 numbers in [0,1], hard/soft/erase strokes), `a` ((0,1], same), `r` ([1,200], any), `s` ((0,1], blur strokes and smudge). Anything else throws. The amend entry itself changes no pixel when reached; instead EVERY fold (page, `Editor.refold`, Node exporter) first runs `HistoryOps.expand(list)`, which returns the list with each amended target replaced by `{...target, ...merged sets}` (amends merged in log order, last wins). Because the whole log is refolded, later entries that depend on the amended pixels (smudge, blur, overlapping strokes) change correctly.
- Undo/redo around an amend: entries recorded BEFORE the amend can no longer restore pixels from stored regions; they become `rebuild` entries (undo = drop the last log entry and refold from scratch). The amend itself is one undo step.
- **Replay** = time-lapse on a separate state and a separate dirty-tile compositor (`ed.replay()`), one log entry per step, total length clamped to 2..8 s, stoppable; it never touches `ops`, undo/redo or the real state; on end/stop the real picture is repainted.
- **Preview** (`ed.preview(k)`): the picture after the first k entries, same machinery; the editor is read-only while previewing (painting logs nothing); `ed.endPreview()` returns to now. No truncation of the log in this level.
- **Verify** (`ed.verify()`): refolds the log from scratch and returns `{ok, head, comp, n, ms}`; `ok` = composite and every layer hash equal the live state; `head` = the hash-chain head (`Stack.chain`) over the log, shown as a 12-char fingerprint.
- **Share-as-link**: URL fragment `#v1=<base64url(deflate-raw(JSON {W, ops}))>&h=<head 16 chars>`. Refused for logs with photos (message: use Save). Opening such a link: payload decoded, chain head recomputed and compared with `h` (mismatch = refuse with a message), then the log opens in a VIEW-ONLY mode: nothing is autosaved, the user's own autosave is untouched, a banner offers Replay and "Edit a copy (replaces your canvas)".
