# PSD export checked with installed apps — red1-Vi, 2026-10-10

## Tools
- available: ImageMagick 6.9.12-98 Q16 (`convert`, lcms2, PSD reader), python3 3.12.3, Pillow 10.2.0 (lcms via ImageCms), numpy; psd-tools 1.24.0 + Pillow 12.3.0 + numpy 2.5.3 in a throwaway venv (system pip is PEP 668 locked, so `python -m venv` outside the repo), node v18.19.1.
- not available (skipped): krita, gimp, magick (IM7), exiftool. Photoshop does not run on Linux and is not claimed.
- sRGB target profile for conversions: `/usr/share/color/icc/colord/sRGB.icc` (system file, intent relative colorimetric).

## Method
Files: `doc/.emit_export/*.psd`. Renders to `/tmp/psdchk` (not in repo). Numbers from `icc/color_math.js` (`dE2000`, selfTest max error 4e-5), compared against `<name>.oracle_srgb.rgba8` (128x128). Every render was opaque in alpha except psd-tools `composite(force=True)` (alpha off by 1 on some pixels).
- `im_raw` = `convert f.psd[0] rgba:` (scene 0 = merged preview, no conversion). `im_srgb` = same plus `-profile sRGB.icc` (embedded -> sRGB).
- `pt_merged_*` = psd-tools `topil()` merged preview; `pt_comp_*` = psd-tools `composite(force=True)` (re-renders layers, psd-tools blend code). `_raw` = `apply_icc=False`; `_srgb` = my own ImageCms conversion of that; `_dflt` = psd-tools defaults (`apply_icc=True`).
- Note: psd-tools applies the embedded ICC by default. My first run double-converted (default + mine) and looked like a failure; the table below is the corrected run.

## Structure (all 5 files: 10 layers, 3 masks, matches `expect.json`)
- psd-tools: modes NORMAL, MULTIPLY, SCREEN, OVERLAY, SOFT_LIGHT, MULTIPLY, DARKEN, LIGHTEN, DIFFERENCE, EXCLUSION; opacity srgb/p3/adobe_mixed 255,156,251,140,185,225,113,155,122,121; p3_pure/embedded_custom 255,160,158,140,162,220,254,173,247,144; masks on layers 1,4,7 (bottom-up index).
- ImageMagick: 11 scenes (merged + 10 layers). Compose per layer (srgb_mixed): Over, Multiply, Screen, Overlay, SoftLight, Multiply, Darken, Lighten, Difference, Exclusion — same as psd-tools. IM has no separate mask scene: layer alpha = layer alpha x mask x opacity, exact (max diff 0 of 255, checked on srgb_mixed and p3_pure, all 10 layers; layer RGB identical to psd-tools). Per-layer IM compose checked on srgb_mixed only.

## What this does and does not show
- Shows: two independent readers (IM/lcms2, psd-tools/PIL lcms) read the embedded profile, layer count, blend modes, opacity and masks as written. Merged preview converted via the embedded profile equals the float64 oracle within 1 level (dE max <= 1.03) in both apps for all five files. Unconverted, the same preview differs by up to 92 levels (dE med 1.6–7.2) so the profile is needed and used. srgb_mixed vs p3_mixed after conversion differs by up to 53 levels / dE max 13.3 — the oracle shows the same, so the difference is real colour (different working-space blends), not a reader fault.
- psd-tools `composite(force=True)` (own layer blend code, approximate) lands within 2–11 levels, dE max <= 2.5 of the oracle; informational only.
- Does not show: Photoshop, Krita, GIMP behaviour (not installed); that IM/psd-tools use the merged preview rather than re-blending layers (IM does not blend; psd-tools `topil` takes the preview); behaviour of any ICC-aware viewer UI prompts (convert-or-keep dialogs).
- No contradiction with README found.
